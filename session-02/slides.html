Do this live in a chatbot. Run A first, let them read the long generic essay. Then run B. Ask: what changed? The model didn't change. Only the prompt did.

The six parts of a good prompt

Read each row. Stress: you don't need all six. Start with a clear task and add parts until the answer is good.

Your turn: fix this prompt

"Improve my resume."

Role: You are a placement trainer. Task: Review the resume summary below. Context: Final-year CSE, applying for backend roles. Format: 3 bullet points, under 20 words each. Rules: Don't invent skills I didn't mention.

Ask the class: what's missing? Collect answers and map each to one of the six parts before revealing.

Four techniques

Zero-shot: just ask

"Is this canteen review positive, negative or neutral? Reply with one word.
Review: The dosa was great but the chai was cold."

→ Neutral

Good for simple, common tasks. Even here, saying the format ("one word") helps.

Few-shot: show, don't tell

Send each complaint to the right department.
Departments: Hostel, Exam cell, Library, Maintenance

Complaint: WiFi in Block C is very slow            → Department: Hostel
Complaint: My internal marks are not updated       → Department: Exam cell
Complaint: Library book return date is wrong       → Department: Library
Complaint: The projector in Room 204 is not working → Department:

→ Maintenance

Use 2–5 varied examples. If every example says "Hostel", it'll say "Hostel" for everything.

Run it live. Then remove the examples and run again: the answer may become a long sentence instead of a label.

Chain-of-thought: think step by step 🧮

"I've attended 36 of 50 classes (72%). 20 classes are left. How many must I attend to reach 75%? Think step by step."

Total = 50 + 20 = 70  ·  75% of 70 = 52.5 → 53
Need 53 − 36 = 17 more classes

Writing the steps = more text to read before the answer = fewer mistakes. Reasoning models do this automatically.

Ask the class to solve it first (give 30 seconds). Many will get it wrong or not finish. Then show the step-by-step answer.

System prompts: rules for the whole chat

SYSTEM: You are "CampusBuddy", helpdesk assistant for ABC Engineering College.
- Answer only questions about the college: exams, fees, hostel, library, placements.
- Under 80 words, simple English.
- If you don't know: "I'm not sure. Please contact office@abc.edu."
- Never share any student's personal details.

USER: Can you write my DBMS assignment for me?

"I can't write your assignment, but I can explain any DBMS topic you're stuck on. Which one?"

Developer writes the system prompt; user never sees it. Every project from now on has one.

JSON output: when code reads the answer

Prompt

Extract name, course, city, wants_hostel (true/false). JSON only.

"Hi, I am Rahul from Mysuru. I want to join B.Tech CSE. Is hostel available?"

Answer

{"name": "Rahul", "course": "B.Tech CSE", "city": "Mysuru", "wants_hostel": true}

  • List fields + types · "JSON only" · temperature 0
  • Use the API's JSON mode · always check with json.loads()

Seven simple tips

  1. Be specific: length, audience, tone
  2. Say what to do
  3. Wrap data in """quotes"""
  4. Allow "I don't know"
  1. One job per prompt
  2. Iterate: write → test → fix
  3. Test with 5–10 real inputs

⚠️ Prompt injection: user text saying "Ignore all previous instructions..." More in Session 5.
